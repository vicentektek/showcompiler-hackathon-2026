# Acceptance and automated QA matrix
Date 2026-10-27. Status: SPECIFICATION for future checks; not a claim that every scenario has been implemented. Offline by default.

## Classification

UNIT = Node test with fake clock / fake transport / mock HTTP. BROWSER = fresh isolated browser profile with rights-clear synthetic WAV and mock upstream service. MANUAL = human listening/physical system test. PAID = an expressly operator-authorized provider call, never run in CI.

Each test must have deterministic fixture IDs, fixed expected events, no secrets, no real hardware by default, explicit evidence, and cleanup of timers/audio/resources.

## Execution batches and evidence

Batch A (run every meaningful integration commit): npm run check:syntax; npm test. CI must not set MODEL_API_KEY or any other provider key.

Batch B (run when ZIP/demo code present): npm run demo:package; independently verify ZIP entry structure; reopen generated package and check SHA-256; run archive tamper tests.

Batch C (run before demo finalization): isolated browser E2E, screenshots/traces on failure, manual safe-volume speaker check, offline check.

Batch D (only after explicit operator authorization): a bounded provider-quality experiment, NOT ordinary CI. No loop/retry.

Coverage reporting must list scenario IDs actually tested; do not mark unimplemented cases 'passed'. A green Node suite is not evidence of speaker output, Windows installation, ASIO, lighting or voice recognition.

## Short acceptance trace for demo

1. Load an original script; line IDs stay literal.
2. A model proposal or clearly labeled prerecorded/mock suggestion references its exact source.
3. Human approves; cue stays non-playing.
4. Load a rights-clear original sound; unresolved GO cannot play until attached.
5. Prepare, press GO exactly once, then STOP/FADE; STOP ALL clears pending follow timers.
6. Export a complete ZIP, reopen in fresh state, inspect source and audio identity, and operate offline.
7. Record commit and test run IDs, then independently verify sound by listening.

The system must not silently skip a failed gate just to complete the demonstration.
